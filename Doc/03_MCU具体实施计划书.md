# 工业涂层质检与追溯系统：MCU 具体实施计划书

版本：V2.0  
日期：2026-10-02  
平台：STM32F4＋FreeRTOS；优先使用现有开发板，具体型号在接线前确认。  
范围：现场输入输出、RS485/Modbus RTU 从站、现场状态机、失联保护、健康检查与看门狗。

通信与命令定义见[整体计划第 9 节](./01_整体项目计划说明书.md#9-通信协议三份文档的共同约定)。主站开发对应[Linux 实施计划](./02_Linux具体实施计划书.md)。

## 1. MCU 的完成条件

STM32 能读取到位开关与操作按钮，作为 RTU 从站接受 Ubuntu 命令，管理当前工位任务并驱动三色指示灯。命令状态或任务标识不匹配时拒绝执行；Linux 失联时撤销合格输出；关键内部任务停滞时由看门狗复位，复位后不恢复旧结果。

涂层厚度采集、工件编号、规则判定、SQLite 和 MQTT 均在 Linux 侧。MCU 使用 session_token 标识当前任务，不保存完整工件业务数据。

## 2. 工作包与实现路径

| 工作包 | 实现方法 | 最小验收 |
|---|---|---|
| M1 现场输入输出 | GPIO、去抖、按键事件、输出管理 | 开关/按钮变化与寄存器、指示灯一致 |
| M2 RTU 从站 | UART DMA、缓冲、RTU 定时、CRC、寄存器 | Ubuntu 实机正常读写与错误响应 |
| M3 工位状态机 | 统一任务处理命令与输入；epoch/token/seq | 非法命令不改变输出，重传不重复执行 |
| M4 失联保护 | 变化的 HOST_HEARTBEAT 与超时门控 | Linux/RS485 中断后及时撤销 |
| M5 健康与看门狗 | 任务进度与 IWDG 条件喂狗 | 停滞可触发复位，健康离线不重启风暴 |

## 3. 硬件与引脚确认

先记录板卡完整型号、芯片型号、时钟配置、可用 USART、DMA stream/channel、调试端口和板上 LED 极性。

| 信号 | 连接对象 | 设计要求 |
|---|---|---|
| UART_TX/RX | RS485 收发器 | 电平匹配，禁止与调试日志混用 |
| RS485_DE | 收发器发送使能 | 上电保持接收态，发送完成后及时释放 |
| WORKPIECE_PRESENT | 到位开关 | 明确有效电平与上下拉，去抖 |
| ACTION | 开始/点位按钮 | 去抖后仅产生一次按下事件 |
| RESET | 业务复位按钮 | GPIO 输入，区别于硬件 NRST |
| LED_PASS | 绿灯 | 启动、故障和失联时关闭 |
| LED_FAIL | 红灯 | 质量 FAIL 指示 |
| LED_FAULT | 黄灯 | 故障/未同步指示 |
| DEBUG_UART/SWO | 调试输出 | 不阻塞通信与控制任务 |

根据线缆与拓扑确定 RS485 终端电阻、偏置和参考地，记录 USB 转换器是否自动控制方向。首版工位用低压按钮和 LED，真实24V设备通过接口电路接入。

引脚和 DMA 路由只有在具体 F4 型号确定后才分配，不照搬其他型号配置。

## 4. 固件目录与三个任务

~~~text
mcu/
├── Core/               # 初始化、IRQ、时钟
├── Drivers/            # CMSIS/HAL
├── Middlewares/        # FreeRTOS
├── BSP/                # UART、GPIO、计时器、IWDG
├── Device/             # RS485、DI、DO
├── Module/             # RingBuffer、RTU、寄存器、健康监视
├── Application/        # 工位状态、命令执行与故障
├── tests/              # 状态机/解析器的主机测试与向量
└── CMakeLists.txt
~~~

| 任务 | 周期/唤醒 | 职责 |
|---|---|---|
| CommTask | DMA/RTU 事件＋有界等待 | 收发、解析、寄存器快照、完整命令入队 |
| WorkstationTask | 10 ms＋事件 | 去抖、工位状态、业务命令、普通输出 |
| HealthTask | 100 ms | 应用心跳期限、任务健康、故障门控、条件喂狗 |

日志使用低开销非阻塞缓冲或限量输出，首版不单独增加复杂 LogTask。优先级与每次处理预算经实测确定，通信压力不能无限占用 CPU。

CommTask 即使没有串口数据也要周期性醒来检查自身健康；不能因没有数据而被误判为死锁。所有任务健康点应在完成一次正常循环后推进，不能由定时中断代为伪造。

## 5. M1：现场输入与输出

### 输入处理

WorkstationTask 每10ms读取输入，以连续稳定若干采样实现去抖。初始可选30ms，后续测实际短按与开关抖动后调整。到位信号作为电平状态，ACTION/RESET 作为按下沿事件。

按键保持不重复生成事件。每个新事件分配 INPUT_EVENT_SEQ，写入事件类型并保持到 ACK_INPUT_EVENT。首版仅一个待确认事件；忙碌期间按键明确报告或计数，不覆盖未处理事件。

ACTION 在 Linux 的 WAIT_ARM、WAIT_CONFIRM 等不同点位步骤有不同作用，MCU 只上报事件，不能自行增加测量点数。RESET 事件由 Linux 读取并在条件满足时发送 RESET_FAULT。

### 输出处理

正常输出由 WorkstationTask 通过 OutputManager 更新：

| 工位情况 | 绿灯 | 红灯 | 黄灯 |
|---|---|---|---|
| 初始化 | 关 | 关 | 关 |
| 未同步/故障 | 关 | 关 | 开 |
| IDLE/READY/INSPECTING | 关 | 关 | 关 |
| 已接受 PASS | 开 | 关 | 关 |
| 已接受 FAIL | 关 | 开 | 关 |

到位消失时清除结果；若仍在检测中则进入故障。蜂鸣器可选，需有限时长避免报警持续占用。

OutputManager 必须有故障覆盖门控：HealthTask 能设置“禁止合格输出”并立即关闭该输出；正常写输出也在短临界区检查门控，防止故障发生后又被另一任务打开。只有合法复位流程能解除覆盖。

## 6. M2：UART DMA 与环形缓冲

复用已有 F4 DMA 工程，按实际 MCU/DMA 路由配置环形 RX。响应 IDLE、DMA 半满与全满事件，维护上次处理位置，计算新增区间并处理跨环形边界。

~~~text
UART 接收 → DMA 缓冲
                 ↓ IDLE/HT/TC
         计算新增区间并有界搬运
                 ↓
          软件 RingBuffer
                 ↓ FromISR 通知
             CommTask
~~~

DMA 缓冲初始可设512字节，软件缓冲1024字节，最终由突发量和任务调度实测确定。生产者/消费者关系明确；位置和溢出标记的访问采取适当原子/临界区保护，不能仅依赖 volatile。

中断只搬运/标记/通知。禁止解析业务、修改工位状态、阻塞日志或等待互斥量。调用 FreeRTOS FromISR API 的中断优先级必须符合实际配置允许范围。

软件缓冲不足时记录溢出，当前帧无效并重新同步；活动检测应触发通信故障。UART ORE/FE/NE 等错误需要记录并按实际 HAL 流程恢复接收，不能持续处于 RX 停止状态。

## 7. M2：RTU 定界、解析与发送

USART IDLE 通常只代表一个字符时间量级的空闲，不能直接认定收到完整 RTU 帧。单独使用定时器/等效串口活动监视处理 t1.5 与 t3.5；115200 下按指南建议采用750μs和1750μs，并通过实际波形验证。

RTU 定时必须反映接收活动，不能等软件任务延迟处理之后才开始计时。根据 DMA 与中断机制设计活动监视，避免把合法连续帧截断或把两个请求拼在一起。

一帧完成后检查地址、功能码、长度、CRC及数量边界。CRC错误和非本机地址通常丢弃并计数；合法格式但功能/地址/数量不支持时返回标准异常。首版不接受广播改变工位业务。

首版功能码：

| 功能码 | 用途 | 限制 |
|---|---|---|
| 0x04 | 读输入寄存器快照 | 地址与数量必须有效 |
| 0x03 | 读保持寄存器 | 配合调试，不能改变状态 |
| 0x06 | 写 HOST_HEARTBEAT | 只允许0x0100 |
| 0x10 | 写业务命令块 | 必须恰好覆盖0x0110～0x0118 |

不允许零散写 OPCODE、token 或结果字段，避免部分更新被执行。整个请求合法后复制完整命令入队，实际执行由 WorkstationTask 完成。

发送步骤：准备完整响应→打开 DE→UART DMA TX→等待 USART TC→关闭 DE→回到接收。DMA搬完内存不代表最后一个停止位已经发出。处理回波与发送期间RX策略，防止自己的响应被当成新请求。

## 8. M3：工位状态机与协议执行

### 状态与编码

| 值 | 状态 | 正常行为 |
|---|---|---|
| 0 | BOOT | 自检、输出关闭 |
| 1 | IDLE | 已同步、无工件 |
| 2 | READY | 到位稳定，等待START |
| 3 | INSPECTING | 绑定token，等待结果 |
| 4 | COMPLETED | 接受了PASS/FAIL |
| 5 | FAULT | 输出撤销，故障锁存 |

初始化后未完成主站同步时处于FAULT。SYNC_SAFE绑定新的host_epoch、清除旧token和输出，仍等待人工复位；健康条件满足的RESET_FAULT使工位进入IDLE或READY。

START只在READY、到位、心跳新鲜、关键任务健康时接受；APPLY_RESULT只在INSPECTING且epoch/token匹配时接受。PASS/FAIL不是两个独立控制源，指示灯不能被另一个寄存器绕过状态机打开。

INSPECTING时到位消失立即撤销输出并FAULT；COMPLETED时正常离开则清除token并回IDLE。由工件离开触发的清除也必须进入状态日志。

### 命令队列与幂等

寄存器、9个命令字段、命令码1～6及ACK_STATUS0～6沿用整体计划第9节，不在本文件另设一套地址。

WorkstationTask检查完整命令后更新ACK_HOST_EPOCH、ACK_CMD_SEQ和ACK_STATUS。协议写响应不能直接写成“业务执行成功”。SYNC_SAFE同时清除上一主站周期未确认的按钮事件，避免在新任务中重放旧按键。

保存最近完成命令的epoch、seq、完整内容与处理结果：

- 完全相同的重传返回原确认，不重复开始、不再次产生输出动作。
- 序号相同但参数不同拒绝。
- 旧epoch、旧序号或不匹配token拒绝。
- 故障后重复旧APPLY_RESULT不得重新打开绿灯；返回原确认时当前状态仍为FAULT。

ACK与状态通过一致快照供主站读取。Linux会同时检查状态与token，因此原确认不能替代当前执行状态。

畸形报文计数与丢弃；非法业务命令明确拒绝。单个CRC错误不应无条件复位整个系统。持续错误导致心跳不再更新时，按超时策略进入故障。

## 9. M4：应用心跳与失联保护

初始心跳周期200ms，超时1500ms。仅变化的HOST_HEARTBEAT刷新last_host_health_tick；相同值、一般读寄存器请求或其他通信活动不代替健康心跳。

MCU要求已经建立有效host_epoch，并看到新鲜心跳后才允许START与故障复位。Linux通信线程只有在业务线程仍健康时才发送变化值。

HealthTask以无符号差值或等效回绕安全方式判断期限。超过期限立即设置输出覆盖门控，撤销PASS/普通输出，并触发FAULT；之后即使心跳恢复也不自动恢复原PASS。

重新上线流程：Linux中止旧检测→SYNC_SAFE→人工RESET→新START。MCU复位后token为无效，Linux必须重新同步，不能假定从站还记得任务。

1500ms只是初始目标。最终测试记录“最后一次有效心跳被接受”到GPIO合格输出关闭的延迟，并包含HealthTask调度误差。内部任务死锁与通信失联属于不同故障，应分别测试。

## 10. M5：健康检查与IWDG

每个关键任务报告上次完整循环时间/进度序号。HealthTask校验CommTask与WorkstationTask，检查缓冲溢出和内部错误；自己完成检查后才喂IWDG。

IWDG超时按所选F4的LSI范围、启动时长与允许恢复时间计算，初始可按约3s设计，最终以实际芯片配置和实测值记录。不要仅凭名义LSI频率声称精确超时。

不在中断或其他无条件周期函数中喂狗。关键任务停滞时先在可运行的健康路径撤销输出，再停止喂狗；HealthTask自身停滞由IWDG兜底。

Linux离线属于可正常处理的外部故障：MCU已进入FAULT且内部任务健康时继续喂狗，避免反复复位。内部任务卡死才触发看门狗恢复。

启动时读取并保存复位原因寄存器，再清除硬件标志，提供RESET_REASON查询。上电、硬复位和IWDG复位均不会恢复上次PASS；按实际硬件有效电平确认GPIO初始化前后的状态。

## 11. 故障与复位规则

建议先实现以下故障码：

| 值 | 故障 | 处理 |
|---|---|---|
| 1 | HOST_TIMEOUT | 撤销输出，锁存 |
| 2 | WORKPIECE_REMOVED | 活动检测中离开，锁存 |
| 3 | RX_BUFFER_OVERFLOW | 当前帧无效，活动检测中止 |
| 4 | TASK_UNHEALTHY | 覆盖输出，停止喂狗或进入可诊断恢复 |
| 5 | HOST_ABORT | Linux因BLE/数据库等原因中止 |
| 6 | HOST_NOT_SYNCED | 启动/重新同步，等待确认 |

故障记录包含触发状态、时间、活动token与关键上下文。只有原因解除、心跳新鲜、任务健康且主站复位命令合法时清除锁存。物理RESET按钮只提出业务复位请求。

在通信已经失效时不能依赖向Linux上报后才关闭输出。错误日志也不能阻塞撤销动作。

## 12. 按顺序实施

- [ ] M0：确定F4具体型号、时钟、USART/DMA/定时器与引脚；完成接线表。
- [ ] M1：到位、ACTION、RESET去抖；三色灯；输出默认态。
- [ ] M2a：UART DMA新增数据提取、跨界、HT/TC、溢出与错误恢复。
- [ ] M2b：RTU定时、CRC、标准读写、RS485 DE/TC实机波形。
- [ ] M3：寄存器快照、完整命令队列、状态机、epoch/token/seq与ACK。
- [ ] M4：应用心跳期限、覆盖门控、人工复位与重新同步。
- [ ] M5：任务健康、IWDG、复位原因和故障日志。
- [ ] M6：与Linux整机联调、故障注入、测试报告。

## 13. 必要测试

| 测试 | 预期证据 |
|---|---|
| 短按、长按、接触抖动 | 事件次数正确；主站轮询能取到短按 |
| 到位中途消失 | MCU主动撤销并报告故障 |
| 分段接收、缓冲跨界、连续帧 | RTU正确分帧，无重复搬运 |
| CRC/长度/功能/地址错误 | 丢弃或标准异常；不能改输出 |
| DE发送时序 | 最后停止位完成后才释放总线 |
| 非法START、旧token、重复结果 | 拒绝/幂等行为及灯具状态一致 |
| 相同心跳反复写入 | 不能持续掩盖主站失活 |
| 拔RS485、杀Linux | 记录输出撤销延迟 |
| Linux业务挂起、串口线程继续 | MCU仍能超时保护 |
| MCU运行中复位 | 输出关闭、token无效、必须新同步 |
| 关键任务停滞 | IWDG复位与原因记录 |
| 外部离线但内部健康 | 保持FAULT而不反复复位 |

UART、RTU与状态机的纯逻辑可在PC上测试；GPIO、DMA、DE、看门狗和时间指标必须上板验证。区分仿真与实机结果。

## 14. MCU交付物

源代码、构建与烧录步骤、板卡/时钟/引脚配置、接线图、寄存器对应实现、故障表、复位原因说明、波形截图与测试报告。

构建优先沿用已有F4工程的GNU Arm工具链、CMake与SWD调试配置；保存具体芯片启动文件、链接脚本、HAL/FreeRTOS版本。输出ELF、BIN/HEX和MAP，提供与实际调试器对应的烧录配置。更换F4具体型号后重新检查内存布局、DMA映射和IRQ，不仅修改芯片名称。

报告记录固件版本、编译选项、实际串口配置、RTU定时、心跳保护延迟、IWDG配置与复位时间。Linux和MCU通过同一PROTOCOL_VERSION匹配，协议改动同步更新两侧测试。
