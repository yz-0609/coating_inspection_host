# 架构与代码阅读指南

## 模块边界

`app/main.cpp` 只负责装配：读取配置、创建队列与健康戳、创建后端、启动线程、处理退出。
业务逻辑在 `domain/worker.cpp`；终端命令在 `cli/commands.cpp`，但仍由业务线程执行，拆文件不改变线程所有权。

建议按以下顺序阅读：

1. `types.hpp`：规则、测量和任务；`protocol.hpp`：工位可观察状态与完整命令。
2. `events.hpp` 与 `support.hpp`：事件复制、有界队列、时钟和业务健康戳。
3. `worker.hpp` 与 `domain/worker.cpp`：唯一业务状态所有者及状态转换。
4. `repository.hpp` 与 `persistence/repository.cpp`：短事务、回滚及结果/Outbox 原子提交。
5. `instrument/instrument.cpp`：原始通知到候选数据的转换和 BLE/回放后端。
6. `workstation/workstation.cpp`：串口独占、轮询、重试、ACK 和心跳。
7. `cli/commands.cpp`、`cloud.hpp`、`app/main.cpp`：操作入口、云端预留与生命周期。

## 线程与数据流

```text
仪器线程（BLE/回放） ──复制后的测量/连接事件──┐
工位线程（Mock/RTU） ──快照/命令完成事件────┼─> 有界队列 ─> 业务线程 ─> SQLite
CLI 输入线程 ────────文本命令────────────┘                  │
                                                         └─> 工位命令队列
业务线程完成正常循环 ─> 健康时间戳 ─> 工位线程 ─> 变化的应用心跳
```

SQLite 连接在业务线程内部创建并释放。自动测试和长稳脚本使用各自独立的查询连接。
队列满时独立 atomic 标志保证故障可见；不丢掉故障后继续确认质量结果。
服务信号处理仅写非阻塞 self-pipe 和置标志，主线程负责协调停止。

## 状态转换的原因

- `START_PENDING`：任务已落库，但尚未获得 MCU 业务确认，不能接收点位。
- `WAIT_ARM`：当前点还没有采集窗口。收到仪器值只记录未归属诊断。
- `WAIT_NEW_MEASUREMENT`：保存窗口单调时间和连接代次，只接受窗口后同代次数据。
- `WAIT_CONFIRM`：每条合法通知生成独立候选编号，多条通知不自动增加点数。
- `FINALIZING`：确认点数并执行最终事务。数据库规则与确认点重新核对判定。
- `COMPLETED`：质量已持久化；现场命令可能仍是 PENDING/UNKNOWN，因此不能宣称已经放行。
- `ABORTED`：原确认点保留；恢复后需要新任务，不能接着旧窗口测量。
- `FAULT`：同步等待人工复位、现场执行异常或系统不可恢复错误，原因在日志中明确记录。

候选编号展示与共享编号更新使用同一互斥锁。工位快照入队时固定已展示候选编号，
ACTION 在处理时用固定编号查找当前窗口候选，不能采用队列中后来到达的新值。
CLI `confirm 编号` 允许确认当前窗口内任何已经展示的候选，候选超过128个触发故障。
人工确认提供业务归属，不能证明探头所在的物理空间点。

## 数据与故障边界

厚度保留有符号 milli_um。阈值配置最多三位小数，拒绝静默舍入；厚度为负但格式合法时仍可成为候选，由规则判定。
FE/NFE 不匹配属于 FAIL；仪器材料为空或未知只作诊断，随后依靠新测量或窗口超时处理。

SQL 迁移位于 `config/migrations/001_init.sql`，CMake 将其嵌入程序。提交失败由 Transaction 析构回滚。
最终结果和 Outbox 不能分开提交；确认点已提交而最终事务失败时，重启仍保留该点并中止未完成任务。

数据库失败时终止性故障关闭健康推进；中止记录若无法写入，会输出明确日志，不能声称已经落库。
磁盘空间每秒检查，开始任务前再检查。数据库写锁等待100ms，串口事务和命令确认都有独立有限期限。

启动恢复只处理中止、待传和未知现场记录，不对旧 PASS 发送 APPLY_RESULT。
对 MCU 重新同步创建新 host_epoch，清除旧 token 和按钮事件；同步拒绝后等待人工重试，不无限创建新 epoch。

## 云端预留

Outbox 的内部 JSON 带 schema_version=1，包含稳定 event_id 和完整确认点。
`ICloudPublisher` 的提交返回值不能等同平台接受；未来回复带 event_id/request_id，明确区分提交和平台确认。
本期 `DisabledCloudPublisher` 返回 NotConfigured，不调用成功回调、不改变尝试计数，也不启动上传线程。
实际 OneNET 编码、认证、TLS、发送调度和补传验收将独立增加。
